# 最基础的 RAG 知识库演示

这个项目演示“先检索、再回答”的流程：收到问题后，服务读取 `knowledge-base/` 中的所有 txt 文件，用关键词找到相关条目，然后返回该条目的内容和来源文件名。这里的“生成”步骤被简化为直接返回知识库原文，方便初学者先理解检索流程；没有调用 AI API。

## 运行

需要 Node.js 18 或更新版本。在本目录执行：

```bash
npm install
npm start
```

服务默认运行在 `http://localhost:3000`。可通过环境变量 `PORT` 修改端口。

## 提问

另开一个终端，发送 JSON 请求：

```bash
curl -X POST http://localhost:3000/ask -H "Content-Type: application/json" -d '{"question":"这个产品是什么？"}'
```

命中知识库时会返回回答和命中的文件名：

```json
{"answer":"企业微信 AI 智能客服系统是一个教学演示产品。它通过查询预先整理的知识库，帮助企业在企业微信场景中回答常见客户问题，并将需要人工处理的问题转给客服人员。","matchedFile":"product.txt"}
```

提问“你们有会员积分吗？”时，由于没有匹配的关键词，返回：

```json
{"answer":"知识库中暂时没有找到相关答案，建议转人工客服处理。","matchedFile":null}
```

缺少 `question` 或传入空字符串时，接口返回 HTTP 400。

## 修改知识库

在 `knowledge-base/` 中编辑或新增 txt 文件。每条知识占两行，条目之间用空行分隔：

```text
关键词：发票，开票
内容：下单后可联系客服申请电子发票。
```

多个关键词用中文逗号 `，` 分隔。保存后，下一次请求就会自动读取更新后的内容。文件可按主题放入 `product.txt`、`faq.txt` 或 `service.txt`；目录中的所有 txt 文件都会参与检索。

## 代码流程与局限

1. `POST /ask` 接收 `question`。
2. 从 `knowledge-base/` 读取并解析所有 txt 知识文件。
3. 检查问题是否包含某个关键词；多个条目命中时，选最长的关键词。
4. 返回对应内容及来源文件名；未命中时返回固定的人工客服提示和 `matchedFile: null`。多个文件命中同长度关键词时，按文件名排序后选择先出现的条目。

关键词匹配无法理解同义词、错别字或复杂语义。真实的 RAG 通常还会使用更强的检索方法，并让语言模型依据检索结果组织回答。
